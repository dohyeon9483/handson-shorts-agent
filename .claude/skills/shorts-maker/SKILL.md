# 쇼츠 만들기 (shorts-maker)

**판단은 spec 한 장, 영상은 거기서 뽑는다.** 어떤 구간을 어떤 순서로, 어떤 제목·화면으로 보여 줄지는 `work/<이름>.json` 에만 적고
`tools/shorts.py` 가 그 spec 으로 영상을 만든다. 고칠 때는 spec 만 고치고 다시 뽑는다.

## 진행 순서

### 1) 받아쓰기 읽기
먼저 `media/샘플정보.md` 와 `media/장면지도.md` 를 읽는다(교정표·이미 만든 예시·6장면 지도·훅 후보).
참여자 자기 영상이면 `media/<영상>.words.json` 이 있는지 보고, 없으면 `python tools/transcribe.py media/<영상>.mp4` 로 먼저 받아 쓴다(→ README 7장). 이때 화면 배치 기본값(강사 정면·가운데)이 맞는지 미리보기로 확인한다. 그다음 `media/*.vtt` 로 강의 전체 흐름을 파악한다(샘플은 2분 남짓).
구간 경계를 정할 때는 `media/*.words.json` 의 낱말 시각(`s`, `e`)을 본다.

### 2) 기획안 3개 제안 — 렌더하지 말고 표로
쇼츠 원칙(리서치 요약):

| 원칙 | 내용 |
|---|---|
| 첫 1~3초 훅 | 결론·질문·숫자를 먼저. 원본 순서를 바꿔도 된다 |
| 한 편에 메시지 하나 | **15~30초**(실습은 렌더 시간 때문에 30초 이하) |
| 2~3초마다 변화 | 제목 교체·레이아웃 전환·확대로 정지 화면을 쪼갠다 |
| 루프 마무리 | 마지막 말이 첫 질문으로 돌아가거나 본편 안내로 끝난다 |

안마다: **제목(훅 문장)**, **쓸 구간**(원본 초, 순서대로), **화면 배치**(구간별 layout), **스타일**(기본형/캡컷식), **예상 길이**.
`샘플정보.md` 의 **이미 만든 예시와 다른 각도**를 우선 제안한다(거기 '아직 안 쓴 각도' 목록이 있다).
마지막에 "어느 안으로 할까요? 고치고 싶은 점도 말해 주세요." 라고 묻는다.

### 3) 고른 안으로 spec 작성 → `work/<짧은이름>.json`
경로는 spec 파일 기준 상대경로: `"src": "../media/<영상>.mp4"`, `"words": "../media/<영상>.words.json"`, `"out": "../out/<짧은이름>.mp4"`.
`샘플정보.md` 의 **교정표를 `replace` 에 꼭 넣는다**(받아쓰기가 고유명사를 틀린다). `media/examples/` 를 열어 비슷한 것을 본뜬다.

**구간 경계**: `in` = 첫 낱말 `s` − 0.05, `out` = 마지막 낱말 `e` + 0.1. 낱말 중간에서 자르지 않는다. 구간은 2.5초 이상.

### 4) 미리보기 → 보여 주고 확인
```bash
python tools/shorts.py work/<이름>.json --preview      # 몇 초. out/<이름>_preview.jpg
```
미리보기 jpg 를 열어(이미지를 읽어) 제목이 잘리거나 얼굴을 가리지 않는지 직접 확인하고, 경로를 알려 준다.

### 5) 렌더
```bash
python tools/shorts.py work/<이름>.json                # 렌더
python tools/shorts.py work/<이름>.json --fps 15       # 급할 때(절반 정도 시간)
```
실측(GPU 없는 인코더 기준, 데스크톱): 기본형 19초 → 83초, 캡컷식 29초 → 153초. 노트북은 1.5~3배 더 걸릴 수 있다.
**실습 시간이 빠듯하면 기본형·20초 안팎을 권한다.** 캡컷식은 그래픽이 매 순간 바뀌어 약 두 배 걸린다.
렌더는 백그라운드로 돌리고, 기다리는 동안 무엇을 했는지 짧게 설명한다. 끝나면 `out/<이름>.mp4` 경로를 알려 준다.

### 6) 수정 요청 반영
"제목 더 짧게", "자막이 얼굴을 가려", "첫 3초를 더 세게", "효과음 넣어 줘" → spec 만 고치고 4)→5).

## spec 레퍼런스

```jsonc
{
  "src": "../media/<영상>.mp4", "words": "../media/<영상>.words.json", "out": "../out/내쇼츠.mp4",
  "fps": 30, "max_chars": 14,                 // 말자막 한 줄 최대 글자(캡컷식은 11)
  "replace": {"틀린 말": "맞는 말"},          // media/샘플정보.md 의 교정표
  "sfx_auto": true,                           // 레이아웃이 바뀌는 경계에 '슉'
  "segments": [ { "in": 29.4, "out": 36.6, "layout": "speaker", ... } ]   // 적힌 순서대로 이어 붙는다
}
```

### 구간(segment) 공통
| 키 | 뜻 |
|---|---|
| `in`, `out` | 원본 초 |
| `layout` | `speaker`(강사 크게, 위에 제목) · `split`(위 그래픽, 아래 강사) · `board`(그래픽 + 원형 강사 창) |
| `speaker` | 원본에서 잘라 올 영역. **샘플 영상 기본값 `{"cx":960,"cy":20,"cw":860}`**, 어둡게 깔려면 `"dim":0.3` |
| `split_y` | split 에서 강사가 시작하는 y(기본 900). split 의 speaker 기본값 `{"cx":960,"cy":180,"cw":880}` |
| `pip` | board 의 원형 강사 창. **샘플 영상 기본값 `{"x":650,"y":300,"size":220,"crop":[640,160,640,640]}`** |
| `titles` | `[{t, t1?, chip?, html, size}]` — `t` 는 구간 안 시각. `<mark>` 는 노란 강조, `<br>` 줄바꿈. 2줄·줄당 10자 안팎, size 80~110 |
| `graphic` | `{"type":"doc", title, rows[], hl_at, hand, hand_at}` 정산서(금액 흐림·'예시') / `{"type":"chart", chip, title, values[], colors[], note}` 막대(‘예시’) |
| `cta` | `{"at":0.6, "y":520, "html":"▶ 본편: …"}` 마지막 안내 버튼 |
| `_why` | 근거 메모(렌더는 무시). "[원본초] 그때 한 말" 을 적어 두면 고치기 쉽다 |

### 캡컷식 — 구간에 `"style":"cc"`
| 키 | 뜻 |
|---|---|
| `cap_mode`, `cap_size` | `box`(지금 낱말 초록 상자·튕김) · `karaoke`(말한 낱말까지 노랗게), 80 |
| `titles[].speed` | 제목 둘레 속도선 깜빡임 |
| `focus` | 확대 중심(얼굴). 샘플 영상 `[960,400]` |
| `cam` | `[{t, z, mode:"cut"\|"push", dur}]` — cut 즉시 펀치인(1.15~1.3), push 천천히(1.08~1.12) |
| `shake` | `[{t, dur:0.4, amp:30}]` 흔들림 |
| `post` | `[{type:"glitch"\|"flash", t, dur}]` 화면 전체 |
| `fx` | `emoji{ch,x,y,size,rot}` · `chip{html,emoji,x,y,rot}` 스티커 · `stamp{text:"✕",x,y,size}` · `search{html,y}` · `glitch_text{text,y}` · `label{text,x,y}` · `big{small,html,y}` · `list{items:[{t,text,emoji}],y}` · `odo{value,unit,dur,to_html,to_at,y}` · `subscribe{x,y}` · `arrow{x,y,text}` — 모두 `t`(구간 안 시각), `t1` 선택 |
| `sfx` | `[{t, kind}]` — pop · ppyong(뿅) · ttaeng(땡) · dudung(두둥) · ding · whoosh (전부 직접 합성) |

강한 효과(글리치·두둥)는 반전에 한 번만. 3초 넘게 아무 변화 없는 화면이 없게.

### 세로 화면 배치 규칙(정해진 값)
위 0~288 은 휴대폰 UI 자리(진행 막대만) · 제목 300~580 · 강사 600~맨 아래 · **얼굴 y 890~1230 은 가리지 않는다** ·
말자막은 y 1420 근처 가운데 · 오른쪽 192px 은 버튼 자리라 비운다. fx 의 `x`,`y` 도 이 범위를 지킨다.

## 막힐 때
- `python tools/check_env.py` — 무엇이 빠졌는지 알려 준다. 결과를 보여 주고, 참여자가 준비를 요청했으면 AGENTS.md '실습 준비 요청' 순서로 고친다.
- 렌더가 너무 느리면 `--fps 15`, 또는 구간을 줄인다.
- 급하면 `media/checkpoints/` 의 spec 을 그대로 렌더해 결과를 먼저 보고 거기서 고친다.
